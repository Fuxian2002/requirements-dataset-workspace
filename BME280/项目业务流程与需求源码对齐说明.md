## 1. 项目定位与对齐基准

本项目是 Bosch BME280 温度、气压、湿度传感器的 C 语言驱动库。它负责寄存器访问、芯片初始化、采样配置、原始数据读取和补偿计算；应用程序负责平台通信、调用时机、结果展示及上层业务。README 中提及的应用场景，不等于仓库已经实现了完整的气象站、物联网平台或告警系统。

- 当前需求文档：[Word](BME280_v8_需求规格说明书.docx) / [PDF](BME280_v8_需求规格说明书.pdf)。
- 源码目录：BME280_SensorAPI-master（`BME280_SensorAPI-master`）。
- 文档声明的基线：SensorAPI v3.5.1，commit `c90d419492e26dd95586598a794e65eb2760753a`。行号以本地对应版本为准，不以持续变化的远端 master 为准。
- 需求范围：22 条功能需求、12 条接口需求、6 条性能需求、6 条可靠性和安全性需求，共 46 条。

对齐关系是“设备能力 → 驱动业务流程 → 需求条款 → API 与内部函数”，而不是仅把头文件函数名改写成需求标题。正常操作、配置副作用、错误传播和调用方责任都属于需求描述范围。

## 2. 涉及设备与责任边界

| 对象 | 在业务中的作用 | 对应代码或责任方 |
| --- | --- | --- |
| BME280 芯片 | 完成温度、气压、湿度转换，提供校准参数和原始数据 | 寄存器及数据定义见 bme280_defs.h（`BME280_SensorAPI-master/bme280_defs.h`） |
| 主控 MCU | 调用驱动、保存设备对象、调度测量和处理结果 | 应用程序；驱动不规定具体 MCU |
| I²C / SPI 总线 | 连接 MCU 与传感器 | `read`、`write` 回调和驱动寄存器接口 |
| 平台计时设施 | 提供微秒延时，安排下一次采样 | `delay_us` 回调及上层定时器/任务 |
| 开发板和 PC | 示例运行、连接及结果输出 | examples/common/common.c（`BME280_SensorAPI-master/examples/common/common.c`）；不是核心库的强制运行设备 |

芯片负责物理转换，驱动负责配置和数值换算，应用负责业务决策。不能将驱动返回的温湿压数值直接表述为已经实现了报警、存储、网络上传或设备控制。

## 3. 主要业务流程

```text
应用绑定通信/延时回调
  → 初始化：读 ID → 校验 0x60 → 软复位 → 等待 NVM → 读取校准参数
  → 配置过采样、滤波、待机时间
  → 选择 Forced 或 Normal 模式
  → 应用等待转换完成或读取状态
  → 读取原始数据 → 温度补偿生成 t_fine → 气压/湿度补偿
  → 应用消费数据，并决定下一次采样
```

1. **建立通信上下文。** 调用方设置接口类型、设备上下文和三个平台回调，保证对象和缓冲区有效。总线初始化和互斥由平台负责。
2. **初始化芯片。** `bme280_init` 检查芯片标识，执行复位并读取校准数据。校准数据是后续补偿的前提，不是可省略的附加信息。
3. **配置采样。** `bme280_set_sensor_settings` 按掩码修改过采样等设置。配置过程中可能进入 Sleep，调用方需要按目标业务重新设置运行模式；不能假定配置后原模式必然保持。
4. **执行采样。** Forced 用于按需触发；Normal 的连续转换由芯片执行，不意味着驱动内部创建了后台线程。转换等待由上层安排。
5. **读取并补偿。** `bme280_get_sensor_data` 读取原始数据，补偿过程依赖温度产生的 `t_fine`。调用者应结合返回码决定是否使用输出，不能只判断缓冲区里是否存在数值。
6. **处理异常和恢复。** 总线失败、设备 ID 不符、NVM 未完成等应结合源码返回路径解释。当前实现存在部分错误被后续操作覆盖的路径，因此“返回成功”不能被扩大解释为每次底层操作都成功。

## 4. 任务划分与运行时序

本项目没有独立 RTOS 任务表，也没有车辆或电池那样的业务状态机。以下“任务”指调用方工作环节，不代表源码中存在同名线程。

| 工作环节 | 触发条件 | 驱动入口 | 调用方应承担的工作 |
| --- | --- | --- | --- |
| 上电准备 | 启动或重新连接 | `bme280_init` | 建立总线和延时回调，检查初始化结果 |
| 参数配置 | 首次启动或参数变化 | `bme280_set_sensor_settings` | 选择配置掩码，处理部分写入和模式副作用 |
| 采样触发 | 定时或按需采样 | `bme280_set_sensor_mode` | 设置模式，避免并发修改同一设备 |
| 时间安排 | 当前过采样参数确定后 | `bme280_cal_meas_delay` | 使用返回的微秒估算值安排等待；该函数本身不等待 |
| 数据交付 | 转换完成后 | `bme280_get_sensor_data` | 检查返回值，按编译分支解释单位 |

测量延时估算范围为 2400～112800 μs，不等于端到端周期或总线延迟保证。DOUBLE、64 位整数和 32 位整数补偿分支的输出单位应按需求文档补偿输出表解释；尤其整数湿度采用 `/1024`，不能误用 `/1000`。

## 6. 不能在对齐说明中省略的实现限制

- 湿度设置失败可能被后续成功的配置覆盖；配置操作不是事务，失败不意味着先前寄存器写入已回滚。
- NVM 轮询中，已有状态值可能使通信错误被 NVM 错误覆盖。需求应记录实际路径，不能只复述理想的错误传播规则。
- SPI 写入会修改调用方地址数组；超长写入存在截断行为。不能套用 BME68x“超限直接报错”的规则。
- 需求文档描述的是当前实现和接口约束，不代表这些实现缺陷已经修复。
- 没有实机验证不能声称达到传感器精度、系统可靠性或实时性指标；芯片数据手册参数也不自动成为整机验收结论。
