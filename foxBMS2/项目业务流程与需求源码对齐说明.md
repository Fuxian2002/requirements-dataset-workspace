## 1. 项目定位与固定基线

foxBMS 2 是电池管理系统固件项目。主要业务是采集电芯和电池串信息，验证测量有效性，执行安全工作区诊断及接触器状态机，估算电池状态、管理均衡，并通过 CAN 与外部控制器交互。仓库还包含独立引导程序、配置、构建工具、测试和文档；这些内容共同支持项目，但不等于需求文档声称覆盖了所有可选驱动和硬件组合。

- 当前需求文档：[Word](foxBMS2_v4_需求规格说明书.docx) / [PDF](foxBMS2_v4_需求规格说明书.pdf)。
- 本地项目：foxbms-2-master（`foxbms-2-master`），版本标记 1.12.0。
- 固定源码：foxBMS2_v3_源码快照.zip（`foxBMS2_v3_源码快照.zip`）。V4 沿用这份源码，不因文档版本提高而假定源码也发生改变。
- 共 58 条需求：48 条功能、4 条性能、6 条可靠性和安全性需求，统一使用 `FBMS-` 前缀；接口说明另列于附录 2。

本说明以默认配置下的应用和引导程序为中心。需求中的“可选能力”“默认启用”和“已经完成硬件验证”必须分别理解。

## 2. 涉及设备及默认选择

```text
电芯/温度传感器 → LTC6813-1 AFE ── SPI ──→ BMS 主控
电流/电压测量  → IVT-S ───────── CAN ──→ 数据库、诊断、估算
外部控制器/充电机 ────────────── CAN ──→ 状态请求
                                                ↓
                                      预充支路、主接触器、均衡
```

| 设备或模块 | 业务作用 | 默认配置与责任边界 |
| --- | --- | --- |
| TMS570LC4357 主控 | 运行 BMS 应用、任务和驱动 | Cortex-R5 平台；底层 HAL/OS 提供执行基础 |
| LTC6813-1 AFE | 电芯电压及辅助通道采集、均衡执行 | SPI/DMA；不是将所有 AFE 变体一并视为默认实现 |
| 温度传感器 | 电池温度测量 | 默认 EPCOS B57251V5103J060 转换配置 |
| IVT-S | 电流、电压及累计电量/能量输入 | CAN 接收；默认电流正值表示放电 |
| 正/负主接触器与预充支路 | 连接高压回路、限制连接瞬间冲击 | 预充反馈默认未配置独立物理反馈，不能宣称实现了完整粘连检测 |
| FRAM | 持久化数据 | SPI 驱动及数据库业务 |
| FS85 SBC、互锁、RTC、板级电源 | 运行监督和辅助设施 | 各自驱动、诊断和调度路径 |
| 外部 VCU、充电机和维护工具 | 状态请求、遥测及固件传输 | CAN，默认 500 kbit/s；协议接入不等于安全认证 |

默认拓扑为 1 串、每串 1 模块、每模块 18 个电芯组；每组并联电芯数为 1，每模块温度点数为 8。默认算法选择 voltage 均衡、counting SOC/SOE、trapezoid SOF，但**全局均衡默认禁用**；IMD、SOH 和冗余配置也不能被写成已经启用的功能。

配置依据见 bms.json（`foxbms-2-master/conf/bms/bms.json`）、battery_system_cfg.json（`foxbms-2-master/conf/bms/battery_system_cfg.json`） 和 battery_cell_cfg.json（`foxbms-2-master/conf/bms/battery_cell_cfg.json`）。配置经过构建生成环节形成头文件，因此应区分配置源、模板与构建产物。

## 3. 主要业务流程

### 3.1 从测量到控制

1. 系统初始化数据库、存储、监督和设备，完成启动阶段的就绪条件。
2. AFE 和 IVT-S 等不同采集路径更新测量数据；数据库是模块交换状态的中心，不是每个业务直接访问硬件。
3. 合理性、有效性和新鲜度检查决定数据是否能用于安全判断；无效值不能直接作为健康测量值参与控制。
4. SOA/诊断形成故障信息；BMS 状态机结合外部请求和故障情况决定接触器操作。
5. SOC/SOE/SOF 估算、均衡和 CAN 上报在各自任务节拍中执行。它们不是每次接触器转换前必须顺序调用的一条串行流水线。

### 3.2 预充与接触器控制

`IDLE`、`STANDBY`、`PRECHARGE`、`NORMAL` 不是无条件自动经过的四个阶段。STANDBY 结合故障和外部 NORMAL/CHARGE 请求决定后续动作。

预充的主要处理为：选择符合条件的电池串 → 等待相关计时条件 → 闭合负接触器并检查反馈 → 闭合预充支路 → 监测电流/压差与故障 → 闭合正接触器并检查反馈 → 断开预充支路 → 进入正常状态。任一环节的反馈、诊断或请求变化都会影响后续转换。

- 当前成功条件使用有效测量，包含绝对电流小于 50 mA、串与母线压差绝对值小于 1000 mV；代码先判断成功，再判断超过 2000 ms 的超时路径。
- 失败处理受最多 3 次尝试及重试等待控制；300 次 BMS 调用在名义 10 ms 周期下约为 3 s，不能把调用次数写成独立硬件定时保证。
- 接触器断开还有专门的到 STANDBY/ERROR 路径，考虑预充支路、主接触器、电流有效性和等待超时；故障状态并不总是简单执行一个立即断开动作。
- ERROR 恢复要求致命故障清除以及明确的 STANDBY 请求，不是条件一好转就自动重新上高压。

这些是当前软件判断，不能替代预充电阻、接触器容量或整套高压回路的电气设计验证。

### 3.3 均衡和状态估算

均衡首先需要全局/局部授权和允许的工作状态，再判断电芯电压、最高温度及相对最低电压的差值。默认未授权时，即使策略代码存在也不表示设备正在均衡。电压策略采用启动阈值和迟滞，通道选择不能简化成“最高电芯始终放电”；显式停用还要清除通道输出。

SOC/SOE 使用 counting 路径以及相关恢复/校正逻辑；SOF 使用 trapezoid 路径和限值层级。配置容量和标称能量是算法输入，不是估算精度经过试验确认的证据。

### 3.4 引导程序与升级

引导程序是独立于主应用的运行镜像。`WAIT` 接收控制请求或处理启动时机；`LOAD` 处理传输顺序、缓冲、校验和写入；`RUN` 验证程序及 CRC 后才跳转；失败可能返回 WAIT 或进入 ERROR，ERROR 当前通过复位处理。不能把 LOAD、RUN、ERROR、RESET 画成无条件串行步骤。

CRC 用于完整性检错，不等同于数字签名、安全启动或固件来源认证。

## 4. 任务调度与业务关系

实际配置见 ftask_cfg.c（`foxbms-2-master/src/app/task/config/ftask_cfg.c`）。以下是名义节拍，不是实测最坏执行时间。

| 任务/节拍 | 核心工作 | 对业务的意义 |
| --- | --- | --- |
| 引擎及启动阶段 | 数据库、FRAM、系统监督及预周期初始化 | 先建立共享基础，再进入周期业务 |
| 1 ms | OS 计时、诊断标志、测量控制、CAN 接收缓冲处理 | 支撑驱动和状态机推进，不表示所有传感器每毫秒产生新值 |
| 10 ms | 系统、互锁、ADC、SPS、CAN、SOF、SBC；每轮 `BMS_Trigger` | 状态机和接触器业务的主调度来源 |
| 10 ms 内分频 | BMS 数据更新首次第 6 次调用，随后每 5 次 | 稳态名义间隔 50 ms；首次相位与稳态周期要分开 |
| 100 ms | 均衡、IMD 调度入口、LED、电源监测等 | 是否具有实际功能仍取决于默认配置 |
| 100 ms 内分频 | SOC/SOE 首次第 11 次调用，随后每 10 次 | 稳态名义约 1 s，不把首次触发与周期混淆 |
| 算法任务 100 ms | `ALGO_MainFunction` | 与其他周期任务分工、分相位运行 |
| I²C 任务 | 扩展器、温湿度/RTC 等驱动，含任务延时 | 不与 1 ms/10 ms 任务强行合并为同步链 |

首次触发计数来自 `ftask_cfg.c` 的分频阈值和计数逻辑，不应误归因于 `BMS_Trigger` 内部的重入计时器。
