## 1. 项目定位与需求基准

本项目是 Bosch BME680/BME688 的 SensorAPI 驱动，负责温度、气压、湿度以及气体电阻测量所需的通信、配置、加热控制、采样和补偿。气体电阻不是 IAQ 指数，也不是某种气体的浓度；这些上层结果需要额外算法和应用条件，不能视为本驱动已经实现。

- 当前文档：[Word](BME68x_v4_需求规格说明书.docx) / [PDF](BME68x_v4_需求规格说明书.pdf)。
- 源码：BME68x_SensorAPI-master（`BME68x_SensorAPI-master`）。
- 固定版本：v4.4.8，对应 commit `80ea120a8b8ac987d7d79eb68a9ed796736be845`；行号以该版本的本地文件为准。
- 需求共 47 条：25 条功能、9 条接口、7 条性能、6 条可靠性和安全性需求。接口需求覆盖 13 个公共 API，并不要求一个 API 必须独占一条需求。

业务对齐的核心是“传感器与平台边界 → 模式和加热配置 → 数据有效性 → 应用可使用的输出”。驱动存在某个分支，不等于所有型号均公开支持该硬件模式。

## 2. 设备及软件责任

| 对象 | 业务作用 | 代码或责任边界 |
| --- | --- | --- |
| BME680 / BME688 | 提供 T/P/H、气体测量、内部加热器和校准数据 | bme68x_defs.h（`BME68x_SensorAPI-master/bme68x_defs.h`） 中的寄存器与数据结构 |
| 主控 MCU | 设置参数、触发测量、消费结果 | 应用程序，不限定具体 MCU |
| I²C / SPI | 主控与传感器交换寄存器数据 | 平台 `read`/`write` 回调及驱动分页逻辑 |
| 平台计时设施 | 实现复位等延时，安排采样周期 | `delay_us` 回调与应用调度 |
| 开发板 / PC | 示例连接和输出 | examples/common/common.c（`BME68x_SensorAPI-master/examples/common/common.c`） |
| 上层气体算法 | 将原始测量进一步解释为应用指标 | 不属于本 SensorAPI 已实现功能 |

加热器位于传感器内部，不能把加热参数描述成控制外部加热设备。本库不创建 RTOS 任务，也不提供设备对象并发互斥。

## 3. 业务流程与关键判断

```text
绑定平台回调
  → 初始化：复位、芯片 ID、variant、校准数据
  → 设置 T/P/H 过采样、滤波和 ODR
  → 设置加热配置并选择运行模式
  → 应用等待转换
  → 读取一条或多条记录、排序并补偿
  → 检查返回码 + n_data + NEW_DATA/GASM_VALID/HEAT_STAB
  → 将有效结果交给上层应用
```

1. **初始化。** `bme68x_init` 识别芯片 ID `0x61`、读取变体和校准参数。当前实现没有承接软复位返回值，因此后续通信成功不能证明前序复位成功。复位实际等待常量为 10000 μs，即 10 ms。
2. **配置测量。** 按实际用途设置过采样、滤波和 ODR。配置及加热设置可能请求进入 Sleep，应用应明确后续运行模式，不能默认采样持续运行。
3. **配置加热。** Forced 使用单段温度/时长；Sequential 的 `heatr_dur_prof` 表示各段毫秒时长并经过编码；Parallel 将该数组值转换为 8 位寄存器编码，用于 TPHG 测量序列重复次数，不能解释为毫秒。Parallel 的 `shared_heatr_dur` 才是以毫秒输入的共享时间。
4. **安排等待。** `bme68x_get_meas_dur` 返回 `uint32_t` 微秒估算值，不是错误码，也不负责等待；应用还要考虑加热、总线和调度开销。
5. **读取结果。** Forced 读取单记录；Parallel/Sequential 路径需要能够容纳 3 条记录的缓冲区，再根据 `n_data` 使用有效的新数据，不能只按期望返回数量分配。
6. **判断可用性。** 返回码、记录数量、新数据位、气体有效位及加热稳定标志各有含义。不能把“读到数据”直接等同于“气体测量结果已经稳定有效”。
7. **处理失败。** 多记录读取存在通信错误被后续结果覆盖的路径；调用方应遵守文档列出的输出有效性约束，不假定所有失败都会原样返回最初错误码。

## 6. 重要约束：需求必须忠实于现有实现

- 多段加热数组需要调用方限制有效长度，现有实现缺少充分的上限防护；不能将建议的 1～10 段写成驱动已经完整执行的检查。
- Parallel 数组值会转成 `uint8_t`。例如 256 变成 0，而不是自动报错；硬件编码 0 有特殊含义，不能理解为“0 ms”。
- 寄存器写入长度超限会返回错误，不采用 BME280 的超长截断规则；地址数组契约也不能从另一项目照搬。
- 默认浮点分支与整数分支输出不同；整数温度按 `/100`、湿度按 `/1000` 换算，浮点湿度不能依据错误注释再乘 1000。
- 回调成功值的实际检查与 `INTF_RET_SUCCESS` 宏的可配置意图不完全一致，应按源码实际比较逻辑解释。
- 模式切换等待没有固定的最大轮询次数；时间估算函数不能据此证明整个调用链具有确定的最坏执行时间。
