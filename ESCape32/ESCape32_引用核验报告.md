## 1 核验方法

四套自动核验 + 四路人工抽样：

| 编号 | 手段 | 脚本 / 载体 | 判定口径 |
| --- | --- | --- | --- |
| E1 | 全量引用的文件存在性与行号区间合法性 | `_qa/_esc32_E_verify.py`、`_qa/_esc32_audit_refs.py` | 文件不存在、起始行 < 1、终止行 < 起始行、终止行超出文件实际行数，任一即判可疑 |
| E1b | 逐节统计需求块数与引用数 | `_qa/_esc32_E_verify.py` | 含 `- 需求标识：` 的节若引用数为 0 即缺陷 |
| E1c | 固定种子分层抽样 80 条逐条回源比对 | `_plan/_E_抽样80条.md` → `_qa/_E_抽样结果_1..4.md` | 打开引用处代码，判断是否支撑正文该句：`支持` / `部分支持` / `不支持` |
| E1d | 表号、图号、附表号、需求 ID 的唯一性与连续性；图题与图片引用配对 | `_qa/_esc32_E_verify.py`、`_qa/_esc32_numbering_check.py`、`_qa/_verify_figs.py` | 重复、缺号、跨章错位、图题与引用文字不一致，任一即判冲突 |

引用形态识别口径（与阶段 B 一致）：

- `path:line` 或 `path:a-b` —— `.c` / `.h` / `.s` / `.S` / `.ld` / `.cmake` / `.txt`；
- `` `path（第 N-M 行）` `` —— `.md` / `.txt` / `.cmake` / `.ld` / `.json` / `.yml` / `.atom`；
- 官方 wiki 只写页面名（`官方 wiki：Settings.md`），不参与行号核验；
- 族级通配引用（`mcu/*/config.c`）按全部匹配文件的最大行数判定。

### 4.2 抽样中发现但不构成缺陷的三点（留痕）

- `mcu/STM32G431/config.c:251-279` 只覆盖 WS2812 三条资源路径中的 G431 一路（G071 / AT32F421 两路由正文另引，未被该条抽中）。

- `prog.c:37` 只显示 `throt_mode` 的 `rearm = 1`，另两项在 `prog.c:48-49`；正文引用为区间写法，无错配。
